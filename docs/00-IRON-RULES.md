## 7. 原站对照清单（防偏离）

**方向：我们对照源站，不是源站对照我们。** Seko 是基准；本站是被测对象。逐项问「我们差源站什么」，禁止反过来说「源站没有我们的某某所以算齐」。


对照入口：§6 Seko URL。**每一项**先截源站同流程作基准，再截本站对照；缺源站基准或只晒本站 = 未验证。只截 stamp/空画布/登录页不算对照。



### 对照维度（每项都要覆盖）

A. **UI** — 布局、层级、点选反馈、空态/忙态/失败态是否像源站（不是「有个类似按钮」）。
B. **功能** — 源站能点的能力本地是否真能走通（导入、参数、LoRA、多参考、i2v、写回…）；未接要老实标空壳，禁止装齐。
C. **实际点击生成** — 必须页面真点 ↑（禁 curl）；对照含生成中→结果回写原卡的成对证据。
D. **本地化源站 HTML** — 本站实现应对齐源站 DOM/结构与交互骨架（胶囊 Composer、节点卡、能力条等），允许皮肤/文案本地化，**禁止**另起一套「看起来像」的空壳 HTML 冒充对齐。

### 必对（P0）

1. **空画布 / 新建节点** — 点「+」得到什么（空白节点 vs 上传）；有无成片真空「+」
2. **分镜/成片卡** — 卡内是否真人成片缩略（图/视频），不是黑卡/裂图/空壳
3. **Composer** — 点中节点才出现；贴节点窄胶囊 vs 压画布大浮层；展开后参数/LoRA/参考图是否齐且可写可发
4. **导入真帖** — 导入后 prompt/底模/LoRA/尺寸是否上屏；看得出在导
5. **能力条** — 选中节点后显示的能力是否跟该节点类型走（勿一套死按钮）
6. **真 ↑ 闭环** — 页面点生成 → 进度/报错 → **写回原卡**（硬刷后还在）；原帖完整参数
7. **多参考 / i2v** — 模型支持几路就露几路；视频吃上游图，不是空壳

### 结构对照（P1，可后于硬闸但要记债）

8. 顶栏信息架构（画布/编辑器等）
9. 左轨（图标轨 vs 成组垃圾堆）
10. 右栏对话（有则对，无则记缺口）
11. 素材库是否有真缩略货

### 明确不算对照

- 只硬刷 stamp / 只看本地写回
- 短 prompt / 点歪 provider 的「成功」
- 未登录 Seko 的猜测截图
- 文本/音频/对口型等未接能力假装已对齐

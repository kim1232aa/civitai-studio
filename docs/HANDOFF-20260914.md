## 3. 调查报告（本轮真机发现并已修的缺陷，按根因分类）

### 3.1 上游协议类
1. **NanoGPT imageDataUrl/imageDataUrls 双发被加总计数**（commit 1c64934）
   - 现象：cap=1 模型（boogu-image/edit）400 IMAGE_INPUT_TOO_MANY，明明只传 1 张。
   - 根因：上游把单数字段与数组字段加总。curl 探针实证（单字段 200 / 双字段 400）。
   - 修法：providers/nanogpt.py `_core_image_body` 单参考只发 `imageDataUrl`。
2. **Civitai /fal/ videoGen resolution 是档位枚举不是像素**（1c64934）
   - wan 家族允许列表为 480p/580p/720p；发 1280x720 撞「不在允许列表」诚实硬门。
   - 修法：前端发 #res 档位 token，io_meta fold 到官方枚举。
3. **HF Inference Providers 子端点字段表**（4e4739b 验证其有效性）
   - HF 模型经路由映射到 fal-ai 等子端点；子端点官方 schema 无 negative_prompt 时
     服务端诚实硬拒「拒绝丢参生成」——铁律设计，实测按预期拦截。
4. **NanoGPT 视频状态嵌套在内层 data.status**（2026-09-15 修复）
   - 现象：t2v 任务上游早已 COMPLETED（curl 直探实证，两单均成片），本地永远 pending。
   - 根因：上游返回 `{"data":{"status":"COMPLETED","output":{"video":{"url":…}}}}`，
     job_status 旧版只读顶层 `data.get("status")` → 空串 → 永远 pending。
   - 修法：providers/nanogpt.py job_status 优先读内层 `data.data.status`（大写由 .lower()
     与映射表 "completed"→"succeeded" 覆盖）；成片 URL 由 _save_result 的 collect_urls
     兜底抓到嵌套 data.output.video.url。两单历史任务修复后立即 succeeded + mp4 落盘。

   修：新增 t2v op（连线规则同 i2v 减 image），前端 op 决策与 currentGraphOp() 对齐。
7. **「文生视频·不需要首帧」frame-slot 被误判为参考输入**（4e4739b）：加 .t2v-no-frame 类，
   `_hasI2vInput` 排除；此前魔搭 t2v 被全面误拦。
8. **Fal UI 参数超发官方 schema**（4e4739b）：kling i2v 无 num_inference_steps/aspect_ratio，

   首版逐项 find_model 使 /api/catalog 18s，已否），UI 标记 + 发送边界 _ofAllow 双拦。
9. **智能匹配覆盖用户手选模型 = 偷换模型**（uservspick，2026-09-15 修复）
   - 现象：fal-t2v 驱动明选 fal-ai/minimax/video-01，出站却发往
     blackforestlabs/flux-3/text-to-video——铁律最禁止的静默换模型。
   - 根因：smartMatchService 的 keepCurrent 对「无家族信息」一律 return false
     （766fefe 为帖子导入 D3 所加），普通手选/新建分镜没有家族字段 → 显式选择被重匹配；
     叠加异步竞态（await 期间的后续选择在注入时被旧搜索结果覆盖）。
   - 修法：fam 为空且非帖子导入（无 diffusionModel/checkpointName 标记）时，
     显式已选且适配当前 op 的模型必须保留；家族严格判定只用于 fam 非空（导入场景）；
     注入前以 sidAtStart 复核选择未在 await 期间变更。修后复测出站确为 minimax/video-01。
   - 同批修：SMART_PREF 的 nano t2v 偏好 id 过期（真实目录 id 无 /text-to-video 后缀，
     task 字段标注），改为 minimax/h3-max 等真实 id。
